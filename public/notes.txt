Ques: Can we write multiple components in the same file ?

- Yes we can, but the main component is single only. Since components are regular js functions, we can write multiple components in same file. Preffered if too small & tightly coupled with the code - else prefer to make it a in a seperate file ( better readability + reusablity)

Note : Components can render other components, but you must never nest their definitions: causes issues and bugs 

export default function Gallery() {  XXXXXXXXXX
  // 🔴 Never define a component inside another component!
  function Profile() { XXXXXXXXX
    // ...
  }
  // ...
}

Note : refer to the link for named vs default exports , explained in detail with eg - https://react.dev/learn/importing-and-exporting-components
- A file can only have one default export, but it can have numerous named exports!

Ques : Is it mandatory for a component to have a default export always ?

- NO , you can have a file which has components only with named exports as well
- Usually agar single compoent banare toh default export use krte other wise mix ya named export use krte 

Ques : Why do multiple JSX tags need to be wrapped? 

JSX looks like html but under the hood gets converted to js objects. One cannot return 2 js object from a js function without wrapping it in an array right...similarly when we want to return multiple elements/components from a component - one has to wrap it in a parent tag like <div>...</div> or a fragment <></> 

Ques : What is the advantage of using a fragment over a div ?

A fragment will group the things and not leave any trace in the browser HTML tree whereas div toh visible hoyega in html tree.
